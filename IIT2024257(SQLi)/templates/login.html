This lab exposes the same login feature in two modes. In Vulnerable mode, the query is built by string-concatenating user input directly into SQL text. In Secure mode, the identical login logic uses parameterized queries (bound placeholders), so the same attack payload is neutralized.

1
Root cause

User-controlled input is concatenated directly into SQL statement text, so attacker data can be interpreted as SQL syntax.

2
Exploit

Username admin' -- turns the rest of the WHERE clause into a SQL comment, skipping the password check.

3
Mitigation implemented

Parameterized queries: SQL is compiled before values are bound, so input is always treated as data, never as code.

4
Other mitigations (theory)

Input allow-listing, least-privilege DB accounts, and generic error messages that don't leak query/schema detail.
