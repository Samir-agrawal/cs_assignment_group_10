## 1. Cross-Site Request Forgery (CSRF)
* **Implemented by:** Samir Kumar (IIT2024274)  
* **Variant:** Variant 2 — POST-based forged action (auto-submitting form)  
* **Directory:** [`./IIT2024274(CSRF)`](./IIT2024274(CSRF)/)

### (a) Vulnerable Implementation
The bank transfer endpoint in [`IIT2024274(CSRF)/server.js`](./IIT2024274(CSRF)/server.js) processes state-changing operations based solely on session cookie authentication:
```javascript
bankApp.post('/transfer', requireAuth, (req, res) => {
  const sender = req.session.username;
  const { recipient, amount } = req.body;

  // Flaw: Accepts state-changing requests without checking proof of user intent
  const result = db.transferFunds(sender, recipient, amount);
  return res.redirect('/dashboard');
});
```

### (b) Working Exploit
The attacker hosts an external page on `http://localhost:4000/claim-prize` containing an invisible, auto-submitting POST form:
```html
<form id="csrfPayloadForm" action="http://localhost:3000/transfer" method="POST">
  <input type="hidden" name="recipient" value="attacker_bob" />
  <input type="hidden" name="amount" value="1000" />
</form>

<script>
  // Submits the request automatically when victim visits the page
  document.getElementById('csrfPayloadForm').submit();
</script>
```
* **Execution:**
  1. Alice logs in to Apex Vault Bank on `http://localhost:3000` (balance: $5,000.00).
  2. Alice visits the attacker page on `http://localhost:4000/claim-prize`.
  3. The form auto-submits. The browser automatically attaches Alice's session cookie.
  4. In Vulnerable Mode, the transfer executes. Alice's balance drops to $4,000.00, and $1,000.00 is credited to Bob Malory without Alice's knowledge or consent.

### (c) Root Cause
The application accepted a state-changing `POST` request relying exclusively on **ambient browser credentials** (session cookies sent automatically with cross-site requests) without requiring a secret, unpredictable proof of intent generated by the legitimate origin.

### (d) Implemented Mitigation
**Anti-CSRF Synchronizer Token Pattern:**
```javascript
if (currentMode === 'MITIGATED') {
  const sessionToken = req.session.csrfToken;
  const submittedToken = req.body._csrf;

  if (!submittedToken || submittedToken !== sessionToken) {
    return res.status(403).send("403 Forbidden: Anti-CSRF Token Missing or Invalid");
  }
}
```
* **Verification:**
  1. On the dashboard, switch defense to **Mitigated Mode**.
  2. Replay exploit from `http://localhost:4000/claim-prize`.
  3. The attacker cannot read Alice's session token due to the Same-Origin Policy (SOP).
  4. The server intercepts the request and blocks it with **HTTP 403 Forbidden**, preserving Alice's account balance.

### (e) Other Mitigations (Theory)
1. **SameSite Cookie Attribute:** Setting `SameSite=Strict` or `SameSite=Lax` to prevent cookies from being attached to cross-site POST requests.
2. **Re-Authentication & Step-Up Verification:** Requiring password re-entry, 2FA OTP, or CAPTCHA before completing sensitive actions.
3. **Custom Headers & CORS Preflight:** Requiring custom headers (e.g., `X-Requested-With`) on API requests, triggering CORS preflight checks that HTML forms cannot bypass.
4. **Avoiding State-Changing GETs:** Enforcing safe HTTP semantics (RFC 7231) by keeping GET requests strictly idempotent.

## 2. OS Command Injection
* **Implemented by:** Sathvik Boina (IIT2024263)  
* **Variant:** Variant 1 — In-band (Command output returned)  
* **Directory:** [`./IIT2024263(Command_Injection)`](./IIT2024263(Command_Injection)/)

### (a) Vulnerable Implementation
A diagnostic route passes user input directly to the system shell interpreter:
```javascript
const { exec } = require('child_process');

app.post('/ping', (req, res) => {
  const host = req.body.host;
  // Flaw: Untrusted input concatenated into shell command
  exec(`ping -c 2 ${host}`, (err, stdout, stderr) => {
    res.send(`<pre>${stdout || stderr}</pre>`);
  });
});
```

### (b) Working Exploit
* **Payload injected in host field:**
  ```text
  127.0.0.1; cat /etc/passwd
  ```
* **Execution:**
  The shell interpreter treats `;` as a command separator, executes `ping -c 2 127.0.0.1`, and subsequently executes `cat /etc/passwd`, returning system password file data in the HTTP response.

### (c) Root Cause
The server passes unsanitized user input directly to a system shell interpreter (`sh`, `bash`), allowing command chaining metacharacters (`;`, `&`, `|`, `` ` ``) to execute arbitrary operating system commands.

### (d) Implemented Mitigation
**Avoid the Shell via Parameterized Execution (`execFile` with Argument Array):**
```javascript
const { execFile } = require('child_process');

app.post('/ping', (req, res) => {
  const host = req.body.host;
  // Direct binary execution: host treated strictly as an argument, no shell spawned
  execFile('/sbin/ping', ['-c', '2', host], (err, stdout, stderr) => {
    res.send(`<pre>${stdout || stderr}</pre>`);
  });
});
```
When injecting `127.0.0.1; cat /etc/passwd`, the binary receives the entire string as a single hostname literal, safely returning an unknown host error without command execution.

### (e) Other Mitigations (Theory)
1. **Allow-list Input Validation:** Validating inputs against strict patterns (e.g., IPv4/IPv6 regex) before processing.
2. **Least-Privilege Process Execution:** Running application processes under dedicated unprivileged system users (e.g., `nobody`, `www-data`).
3. **Native Programming APIs:** Using built-in language networking libraries (e.g., `net`, `dns`) rather than spawning external shell processes.

## 3. SQL Injection (SQLi)
* **Implemented by:** G.P. Chandra Sekhar (IIT2024257)  
* **Variant:** Variant 1 — Authentication Bypass  
* **Directory:** [`./IIT2024257(SQLi)`](./IIT2024257(SQLi)/)

### (a) Vulnerable Implementation
The login route dynamically constructs SQL queries via string concatenation:
```javascript
const query = `SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`;
db.get(query, (err, row) => {
  if (row) {
    req.session.user = row.username;
    return res.redirect('/dashboard');
  }
  return res.status(401).send("Invalid credentials");
});
```

### (b) Working Exploit
* **Payload injected into username field:**
  ```sql
  admin' --
  ```
  *(Alternative: `admin' OR '1'='1' --`)*
* **Resulting Query Executed by Database:**
  ```sql
  SELECT * FROM users WHERE username = 'admin' --' AND password = '...'
  ```
  The SQL comment sequence (`--`) truncates the query, bypassing the password verification clause and granting instant administrative access without valid credentials.

### (c) Root Cause
The application constructs database commands by directly interpolating unvalidated, unsanitized user input into the SQL command string, allowing user-supplied metacharacters to modify query logic.

### (d) Implemented Mitigation
**Parameterized Queries (Prepared Statements):**
```javascript
const query = `SELECT * FROM users WHERE username = ? AND password = ?`;
db.get(query, [username, password], (err, row) => {
  // Input treated strictly as literal string parameters
});
```
When injecting `admin' --`, the database searches for a user whose literal username equals `admin' --`. The exploit fails and returns 401 Unauthorized.

### (e) Other Mitigations (Theory)
1. **Allow-list Input Validation:** Enforcing strict alphanumeric constraints on username and credential inputs, rejecting SQL metacharacters (`'`, `"`, `;`, `--`).
2. **Least-Privilege Database Accounts:** Executing web queries using dedicated database users granted only minimum necessary read/write privileges, prohibiting administrative or DDL actions.
3. **Safe Error Handling:** Suppressing detailed database errors and stack traces to avoid leaking database schema information to attackers.

## 4. Cross-Site Scripting (Reflected XSS)
* **Implemented by:** Ashish Bairwa (IIT2024261)  
* **Variant:** Variant 2 — Reflected XSS  
* **Directory:** [`./IIT2024261(Reflected_XSS)`](./IIT2024261(Reflected_XSS)/)

### (a) Vulnerable Implementation
The application accepts query parameters and reflects them directly into the HTML response without output encoding:
```javascript
app.get('/search', (req, res) => {
  const query = req.query.q || '';
  res.send(`
    <h1>Search Results</h1>
    <p>You searched for: ${query}</p>
  `);
});
```

### (b) Working Exploit
* **Crafted Malicious URL:**
  ```text
  http://localhost:3000/search?q=<script>alert(document.cookie)</script>
  ```
* **Execution:**
  When a victim accesses the link, the server embeds the raw script tag into the HTML response. The victim's browser interprets the `<script>` tag as executable JavaScript, executing the payload within the trusted origin context.

### (c) Root Cause
The application reflects untrusted input directly into HTML output without context-aware output encoding or sanitization, causing the browser to execute user data as markup and code.

### (d) Implemented Mitigation
**Context-Aware HTML Entity Encoding:**
```javascript
function escapeHTML(str) {
  return str.replace(/[&<>'"]/g, tag => ({
    '&': '&amp;',
    '<': '&lt;',
    '>': '&gt;',
    "'": '&#39;',
    '"': '&quot;'
  }[tag] || tag));
}

app.get('/search', (req, res) => {
  const query = escapeHTML(req.query.q || '');
  res.send(`<h1>Search Results</h1><p>You searched for: ${query}</p>`);
});
```
The characters `<` and `>` are encoded as `&lt;` and `&gt;`. The browser renders the text literally on the page without executing it.

### (e) Other Mitigations (Theory)
1. **Framework Auto-Escaping:** Using template engines (e.g., React, Angular, EJS) that automatically encode dynamic data.
2. **HTML Sanitizers:** Using libraries such as DOMPurify to strip executable scripts when rich HTML input is required.
3. **Content Security Policy (CSP):** Specifying `Content-Security-Policy: default-src 'self'` to prohibit inline `<script>` tags and untrusted script sources.
4. **HttpOnly Cookie Flag:** Preventing theft of session tokens via XSS by setting `HttpOnly` on sensitive authentication cookies.
5. **Safe DOM Sinks:** Preferring safe browser DOM methods (`textContent`, `createElement`) over dangerous sinks (`innerHTML`, `eval`).
